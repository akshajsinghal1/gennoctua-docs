## List Brands

Returns all registered brands.

```http
GET /admin/brands
x-admin-secret: YOUR_ADMIN_SECRET
```

### Response

```json
[
  {
    "id": 1,
    "brand_key": "gn_pk_mauijim_a3f8c2d1e4b5f6a7",
    "brand_name": "Maui Jim",
    "active": 1,
    "created_at": "2026-05-06 10:25:34"
  },
  {
    "id": 2,
    "brand_key": "gn_pk_acme_b9d3e1f2a4c6",
    "brand_name": "Acme Fashion",
    "active": 0,
    "created_at": "2026-04-01 08:00:00"
  }
]
```

| Field | Type | Description |
|---|---|---|
| `id` | `number` | Auto-incremented database ID |
| `brand_key` | `string` | The `gn_pk_...` brand key |
| `brand_name` | `string` | Human-readable brand name |
| `active` | `0 \| 1` | `1` = active, `0` = deactivated |
| `created_at` | `string` | ISO timestamp of registration |

<Note>
The `hp_api_key` is never returned in API responses for security reasons.
</Note>

### Example

```bash
curl https://api.gennoctua.com/admin/brands \
  -H "x-admin-secret: YOUR_ADMIN_SECRET"
```

## Add a Brand

Register a new brand and their HyperPersona API key.

```http
POST /admin/brands
x-admin-secret: YOUR_ADMIN_SECRET
Content-Type: application/json
```

### Request Body

```json
{
  "brandKey": "gn_pk_mauijim_a3f8c2d1e4b5f6a7",
  "brandName": "Maui Jim",
  "hpApiKey": "hpk_ZMtMItJxHOvvJkY9eGU12dJKRMB-bsJP3xoYSyRphAc"
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `brandKey` | `string` | ✅ | The `gn_pk_...` key you generated for this brand |
| `brandName` | `string` | ✅ | Human-readable name (for your reference) |
| `hpApiKey` | `string` | ✅ | The brand's HyperPersona API key |

### Response

```json
{ "success": true }
```

### Errors

```json
// Missing fields
{ "error": "brandKey, brandName, hpApiKey are required" }

// Duplicate key
{ "error": "Brand key already exists" }
```

### Example

```bash
curl -X POST https://api.gennoctua.com/admin/brands \
  -H "x-admin-secret: YOUR_ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "brandKey": "gn_pk_mauijim_a3f8c2d1e4b5f6a7",
    "brandName": "Maui Jim",
    "hpApiKey": "hpk_ZMtMItJxHOvvJkY9eGU12dJKRMB-bsJP3xoYSyRphAc"
  }'
```

## Deactivate a Brand

Deactivates a brand. Their SDK will immediately start failing with `AUTH_INVALID`. The brand record is not deleted — it can be reactivated.

```http
DELETE /admin/brands/:brandKey
x-admin-secret: YOUR_ADMIN_SECRET
```

### Path Parameters

| Parameter | Description |
|---|---|
| `brandKey` | The `gn_pk_...` key of the brand to deactivate |

### Response

```json
{ "success": true }
```

### Example

```bash
curl -X DELETE https://api.gennoctua.com/admin/brands/gn_pk_mauijim_a3f8c2d1e4b5f6a7 \
  -H "x-admin-secret: YOUR_ADMIN_SECRET"
```

### What Happens After Deactivation

Once deactivated:
- `POST /auth/token` returns `401 Invalid or inactive brand key`
- Any in-flight JWTs remain valid until their 1hr expiry
- The brand's website will stop working after those tokens expire

To immediately invalidate in-flight tokens, rotate your `JWT_SECRET` on the server (this invalidates **all** active tokens for all brands).

## Auth Endpoints (used by SDK)

These endpoints are called automatically by the SDK. Documented here for reference.

### Get Token

Called by the SDK when a brand uses `publicKey` auth mode.

```http
POST /auth/token
Content-Type: application/json
```

```json
{
  "publicKey": "gn_pk_mauijim_a3f8c2d1e4b5f6a7"
}
```

**Success:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresIn": 3600
}
```

**Invalid key:**
```json
{ "error": "Invalid or inactive brand key" }
```

### Submit Try-On Job

Called by the SDK to submit a try-on job.

```http
POST /api/tryon/submit
Authorization: Bearer <jwt>
Content-Type: multipart/form-data
```

**Form fields:**

| Field | Type | Description |
|---|---|---|
| `user_image` | `File` | The selected profile photo |
| `garment_image_url` | `string` | Product image URL |
| `product_type` | `string` | Descriptive label (e.g. `"sunglasses"`) |
| `category` | `string` | Broad category (e.g. `"eyewear"`) |

**Response:**
```json
{
  "job_id": "165bd069-8ac9-4e92-9a13-d9e1dfd00fe4",
  "status": "QUEUED"
}
```

### Stream Job Status

Called by the SDK to poll for job completion via SSE.

```http
GET /api/tryon/status/:jobId
Authorization: Bearer <jwt>
Accept: text/event-stream
```

**SSE events:**

```
data: {"status": "PROCESSING", "job_id": "165bd069..."}

: keepalive

data: {"status": "COMPLETED", "job_id": "165bd069...", "result_url": "https://storage.googleapis.com/..."}
```

| Status | Meaning |
|---|---|
| `QUEUED` | Job is waiting to be processed |
| `PROCESSING` | AI generation in progress |
| `COMPLETED` | Try-on image ready — `result_url` contains the image URL |
| `FAILED` | Generation failed — retry |
