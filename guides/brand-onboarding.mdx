## Overview

<Warning>
This guide is for **Gennoctua team members only**. It contains admin credentials and internal processes. Do not share with clients.
</Warning>

This guide is for **Gennoctua team members** onboarding a new brand.

When a new brand signs up:
1. You get their HP API key
2. You generate a brand key for them (`gn_pk_...`)
3. You register them in the database
4. You send them their brand key
5. They integrate the SDK with one line of code

---

## Step 1 — Get Their HP API Key

The brand's HP API key comes from the HP dashboard. It looks like:

```
hpk_ZMtMItJxHOvvJkY9eGU12dJKRMB-bsJP3xoYSyRphAc
```

This key is tied to their usage quota in HP.

---

## Step 2 — Generate a Brand Key

Brand keys follow the format: `gn_pk_{brandname}_{random}`

**Generate a random suffix:**
```bash
node -e "console.log('gn_pk_brandname_' + require('crypto').randomBytes(8).toString('hex'))"
```

**Example output:**
```
gn_pk_mauijim_a3f8c2d1e4b5f6a7
```

Keep the brand name short and lowercase. Use underscores for spaces.

---

## Step 3 — Register in the Database

Call the Admin API on the Gennoctua backend:

```bash
curl -X POST https://api.gennoctua.com/admin/brands \
  -H "x-admin-secret: YOUR_ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{
    "brandKey": "gn_pk_mauijim_a3f8c2d1e4b5f6a7",
    "brandName": "Maui Jim",
    "hpApiKey": "hpk_ZMtMItJxHOvvJkY9eGU12dJKRMB-bsJP3xoYSyRphAc"
  }'
```

**Success response:**
```json
{ "success": true }
```

**If brand key already exists:**
```json
{ "error": "Brand key already exists" }
```

---

## Step 4 — Verify Registration

```bash
curl https://api.gennoctua.com/admin/brands \
  -H "x-admin-secret: YOUR_ADMIN_SECRET"
```

You should see the new brand in the list:
```json
[
  {
    "id": 1,
    "brand_key": "gn_pk_mauijim_a3f8c2d1e4b5f6a7",
    "brand_name": "Maui Jim",
    "active": 1,
    "created_at": "2026-05-06 10:25:34"
  }
]
```

---

## Step 5 — Send the Brand Key

Send the brand their key. They only need this one value:

```
gn_pk_mauijim_a3f8c2d1e4b5f6a7
```

Include a link to the [Frontend-Only Integration Guide](/integration/frontend-only) or the [Vibe Coder Guide](/guides/vibe-coder) depending on their technical level.

---

## Step 6 — Brand Integrates

The brand adds the SDK to their website:

```html
<script src="https://cdn.jsdelivr.net/gh/akshajsinghal1/gennoctua-sdk@main/dist/cdn/personalize.min.global.js"></script>
<script>
  window.Personalize.init({
    auth: {
      publicKey: "gn_pk_mauijim_a3f8c2d1e4b5f6a7"
    }
  });
</script>
```

That's it. The SDK handles token fetching, proxying, and caching automatically.

## Managing Brands

### List all brands

```bash
curl https://api.gennoctua.com/admin/brands \
  -H "x-admin-secret: YOUR_ADMIN_SECRET"
```

### Deactivate a brand

```bash
curl -X DELETE https://api.gennoctua.com/admin/brands/gn_pk_mauijim_a3f8c2d1e4b5f6a7 \
  -H "x-admin-secret: YOUR_ADMIN_SECRET"
```

Deactivated brands can no longer fetch tokens. All subsequent SDK calls will fail with `AUTH_INVALID`.

### Reactivate a brand

Direct database update (no API endpoint yet):
```bash
# SSH into server and run:
sqlite3 ~/gennoctua-backend/brands.db \
  "UPDATE brands SET active = 1 WHERE brand_key = 'gn_pk_mauijim_a3f8c2d1e4b5f6a7'"
```

## What Happens at Runtime

Once the brand is registered, every shopper visit triggers this flow:

```
1. Brand's page loads
2. SDK calls POST /auth/token with their gn_pk_... key
3. Gennoctua validates key → returns 1hr JWT
4. Shopper uploads photos → processed locally in browser
5. Shopper clicks Try On
6. SDK calls POST /api/tryon/submit with JWT
7. Gennoctua validates JWT → looks up hp_api_key → forwards to HP
8. HP generates image → SSE stream back to browser
9. Result cached in browser for 7 days
10. Shopper sees the try-on (~20 seconds total)
```
